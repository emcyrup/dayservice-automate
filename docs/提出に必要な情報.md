# 国保連への伝送・LIFEへの提出に必要な情報

CareOne(訪問介護)から**国保連合会へ請求データを伝送**する場合と、**LIFEへ評価データを提出**する場合に、それぞれ何が揃っている必要があるかの一覧です。

作成日: 2026-08-25 / 対象: CareOne(訪問介護)

アプリ内でも同じ内容を確認できます。

- 🧾請求タブ →「📤 請求データ」→ **国保連へ伝送するために必要なもの**
- 🧬LIFEタブ →「📤 提出データ」→ **LIFEへ提出するために必要なもの**

いずれも、いま登録されている内容から**足りない項目を利用者名つきで表示**します。

---

## 1. 国保連への請求(介護給付費請求)

### 1-1. 事業所として必要なもの

| 項目 | 用途 | 登録場所 | 状態 |
|---|---|---|---|
| **事業所番号**(10桁) | 請求事業所・送付元の識別 | ⚙️設定 → 事業所情報 | ✅ 登録可 |
| **事業所名** | 明細書・帳票の表示 | ⚙️設定 → 事業所情報 | ✅ 登録可 |
| **保険者番号**(6桁) | 請求先市町村の識別 | ⚙️設定 → 事業所情報(利用者ごとに違う場合は🏡利用者側) | ✅ 登録可 |
| **サービス種別コード** | 訪問介護は「11」 | 固定値 | ⚠️ 暫定(仕様突合が必要) |
| **地域区分の単位単価** | 単位数 → 金額の換算 | ⚙️設定 → 単位単価 | ✅ 登録可 |
| **算定する加算・減算の体制** | 加算の算定可否 | ⚙️設定 → 単位数マスタ | ✅ 登録可 |
| **体制届の提出済みであること** | 届出のない加算は返戻 | 📑申請タブで作成 → 保険者へ提出 | ✅ 下書きまで |
| **電子証明書**(介護保険証明書) | 伝送時の本人確認・暗号化 | **アプリ外**。電子請求受付システムでオンライン申請。手数料あり・有効期間3年 | ⛔ 本番項目 |
| **電子請求受付システムのユーザID・パスワード** | 伝送のログイン | **アプリ外**。国保連から通知 | ⛔ 本番項目 |
| **代理人申請・委任状** | 代理請求する場合のみ | **アプリ外** | ⛔ 本番項目 |

### 1-2. 利用者ごとに必要なもの

すべて 🏡利用者タブ →「編集」から登録します。

| 項目 | 状態 |
|---|---|
| **被保険者番号**(10桁) | ✅ |
| **氏名 / 氏名カナ** | ✅(氏名カナは今回追加) |
| **生年月日** | ✅(今回追加) |
| **性別** | ✅(今回追加) |
| **要介護度** | ✅ |
| **認定有効期間**(開始・終了) | ✅(今回追加)期限切れは請求前チェックで⛔表示 |
| **区分支給限度基準額** | ✅ 要介護度から自動(⚙️設定で編集可) |
| **利用者負担割合**(1〜3割) | ✅ |
| **居宅介護支援事業所番号**(ケアプラン作成事業所) | ✅(今回追加) |
| **保険者番号**(利用者ごと) | ✅(今回追加。空欄なら事業所設定の値を使用) |
| 公費受給者番号・公費負担者番号 | ⛔ 未対応(生活保護等の併用がある場合に必要) |
| 特定入所者介護サービス費・高額介護サービス費 | ⛔ 未対応(訪問介護では通常不要) |

> **返戻の三大要因**は「認定情報の不一致(有効期間切れ・要介護度の相違)」「被保険者番号の誤り」「体制届を出していない加算の算定」です。この3つは請求前チェックで検出しています。

### 1-3. 明細(サービス提供の実績)として必要なもの

| 項目 | 状態 |
|---|---|
| サービス提供年月 | ✅ 報告から自動 |
| サービスコード(6桁) | ⚠️ ⚙️設定の単位数マスタで管理(コード体系の突合が必要) |
| 単位数・回数・合計単位数 | ✅ 報告の所要時間から自動計算 |
| 加算・減算の内訳と適用順 | ✅ 実装済み(明細書で確認可) |
| 保険給付額・利用者負担額 | ✅ 自動計算 |
| **サービス実施日ごとのレコード**(日単位の提供日) | ⛔ 未実装(現在は月次集計まで) |

### 1-4. ファイル形式・伝送

| 項目 | 内容 | 状態 |
|---|---|---|
| レコード構成 | コントロール / データ / エンド の3種 | ✅ 試作済み |
| 区切り・改行 | カンマ / CRLF | ✅ |
| 文字コード | **Shift_JIS系** | ⛔ 現在はUTF-8(BOM付き)。本番はサーバ側で変換 |
| 交換情報識別番号 | 様式・サービス種別ごとに異なる | ⛔ 仕様書突合が必要 |
| ファイル名の命名規則 | 仕様書で規定 | ⛔ 未確定 |
| 提出期限 | サービス提供月の**翌月1日〜10日** | ― |

詳細は [`docs/国保連請求_仕様メモ.md`](国保連請求_仕様メモ.md) を参照してください。

### 1-5. まとめ:いま伝送するには何が足りないか

1. **電子証明書の取得**(事業所側の手続き。ここが最初の一歩)
2. **インタフェース仕様書との突合** — 交換情報識別番号・項目順・桁数の確定
3. **Shift_JIS出力**(サーバ側変換)
4. **サービス実施日レコード**の追加
5. **公費併用**への対応(必要な事業所のみ)
6. **返戻・過誤データの取込**

## 2. LIFE(科学的介護情報システム)への提出

> **前提**: 訪問介護は現時点でLIFE関連加算の**対象外**です。CareOneのLIFE機能は、対象拡大への備えと、通所介護等を併設する法人での一括運用を想定した**先行実装**です。詳細は [`docs/LIFE連携.md`](LIFE連携.md)。

### 2-1. 事業所として必要なもの

| 項目 | 内容 | 状態 |
|---|---|---|
| **事業所番号**(10桁) | 提出データの識別 | ✅ ⚙️設定 |
| **LIFEのアカウント** | 電子請求受付システムのIDでログイン。管理者アカウントで**操作職員(ケア記録責任者など)**を登録 | ⛔ アプリ外の手続き |
| **対象サービス種別であること** | 施設系・通所系・居住系など | ⚠️ 訪問介護は対象外 |
| **LIFE関連加算の届出** | 科学的介護推進体制加算などの体制届 | ⛔ アプリ外 |

### 2-2. 利用者ごとに必要なもの

| 項目 | 状態 |
|---|---|
| **被保険者番号** | ✅ |
| **氏名 / 氏名カナ** | ✅(氏名カナは今回追加) |
| **生年月日** | ✅(今回追加) |
| **性別** | ✅(今回追加) |
| **要介護度** | ✅ |
| **保険者番号** | ✅(今回追加) |
| サービス利用開始日 | ⛔ 未対応 |

### 2-3. 評価データとして必要なもの

CareOneが現在持っている項目:

| 区分 | 項目 |
|---|---|
| ADL | Barthel Index 10項目(100点満点) |
| 栄養 | 身長・体重・BMI |
| 口腔 | 食べこぼし・むせ・歯や義歯の汚れ・義歯不適合・口腔乾燥 |
| 認知症の行動・心理症状 | DBD13(13項目 × 0〜4点) |
| 意欲 | Vitality Index(5項目 × 0〜2点) |
| その他 | 服薬中の薬剤数・特記事項・評価日 |

**本番までに突合が必要なもの**(厚生労働省 [LIFE CSV連携仕様書](https://www.mhlw.go.jp/content/12301000/001242214.pdf) 3.00版):

- 各項目の**コード値・桁数・必須/任意**の確定
- 「科学的介護推進に関する評価」様式のうち未実装の項目 ― **既往歴・服薬情報(薬剤名)・褥瘡の有無・認知症の状況**など
- 興味・関心チェックシート、口腔・栄養スクリーニング、排せつ支援などの**他様式**

### 2-4. 提出のルール

| 項目 | 内容 |
|---|---|
| 頻度 | 原則 **3か月に1回**(利用開始時・変化時にも評価) |
| 期限 | 加算算定月は、サービス提供月の**翌月10日まで** |
| 提出方法 | LIFEにログインしてCSVアップロード(またはLIFE上で直接入力) |
| **フィードバックの活用** | 加算要件は「提出」だけでなく**返ってきたフィードバック票をケアの見直しに使うこと**まで含みます |

### 2-5. まとめ:いま提出するには何が足りないか

1. **CSV連携仕様書との突合**(項目定義・コード表)
2. 未実装項目(既往歴・服薬情報・褥瘡・認知症の状況)の追加
3. **フィードバック票の取込**機能
4. LIFEへの直接アップロード(現在はCSV出力まで)

## 3. 検証時のお願い

検証版は認証・暗号化のない試用環境です。**実在の被保険者番号・生年月日・氏名は入力しないでください。** 桁数だけ合わせた仮の値でお試しください。
