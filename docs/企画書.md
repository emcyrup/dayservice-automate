# そだちノート ─ 福祉現場の記録・共有AI(企画書 v0.2)

> 放課後等デイサービス・訪問介護の現場向けに、**「話す/送るだけで貯まる記録」から書類・報告・計画を自動生成**し、**支援者情報の共有で誰もが安心して支援に入れる**ようにするSaaS。

作成日: 2026-07-22 / 更新: 2026-07-22(v0.2) / ステータス: 企画ドラフト

## v0.2 での変更点

- **入口を「LINE/音声で貯める」方式に刷新**(その場でキーワード送信→あとでボタン一発生成)
- **支援者情報共有(セーフティノート)を目玉機能として追加** ― 名前を入れると注意事項が返る
- **活動計画・狙いの下書き生成**を追加(個別支援計画に加えて)
- **訪問介護領域への展開**を追加(報告の一本化・移動記録・買い物支援)
- セキュリティ要件を強化(権限管理・閲覧ログ・退職者遮断)

## 1. 背景と課題

### 放課後等デイサービス

| 現場の痛み | 具体的な状況 |
|---|---|
| 毎日の記録が重い | 児童ごとの活動記録を閉所後にまとめて入力。記憶が薄れ、残業になる |
| 保護者への報告が手間 | 連絡帳・アプリで一人ひとりに文章を作成 |
| 個別支援計画・活動計画 | 6ヶ月ごとの計画に加え、日々の活動計画・狙いの言語化も負担 |
| **担当者しか子どもの情報を知らない** | **臨時対応・ヘルプ勤務時に配慮点が分からず、事故・トラブルのリスク。スタッフの不安も大きい** |
| 加算申請書類の不備 | 算定要件の根拠記録の抜けが、実地指導で返還リスクに |

### 訪問介護(新規)

| 現場の痛み | 具体的な状況 |
|---|---|
| 報告の三重入力 | ①手書きの報告書 ②記録アプリ(例: ケアピア)への入力 ③サービス提供責任者への要約報告 ― 同じ内容を3回作っている |
| 移動記録が手間 | 支援時の移動ごとに走行距離・メーター値・所要時間の報告。買い物支援があると報告回数がさらに増える |
| 買い物支援の非効率 | 利用者が買ってほしい物を選ぶのに時間がかかる |

**共通する本質**: 記録は「その場で断片的に発生」するのに、書類は「あとでまとまった文章」を要求される。このギャップを人が埋めているのが残業と負担の正体。

## 2. コンセプト

> **「その場では、送るだけ。書類は、ボタン一発。」**
> **「名前を入れれば、配慮点がわかる。誰でも安心して支援に入れる。」**

### 共通エンジン: 「貯めて → 生成」

```
[現場・その場]                       [あとで・ボタン一発]
 音声で話す ──┐
              ├─→ 児童/利用者ごとに ──→ AIが各種書類に自動生成
 LINEにキーワード┘    時系列ストック         (記録・報告・計画・要約…)
 を送る
```

- スタッフは**その瞬間に一言送るだけ**(「たろう ブロック集中 順番待てた」)
- 音声派・テキスト派どちらにも対応。LINEは現場が既に使い慣れている
- 閉所後・支援後に「生成」ボタン → 必要な書式すべてが下書きされる

## 3. 機能構成

### コア(両領域共通)
1. **貯める**: 音声入力 / LINE(Messaging API)でキーワード・メモをストック
2. **生成する**: ストック+過去の記録を材料に、AIが書式ごとの文章を下書き
3. **人が確定する**: 必ずスタッフ・責任者がレビュー・承認してから確定/送信

### 放課後デイサービス向け

| 機能 | 内容 | フェーズ |
|---|---|---|
| 活動記録の自動生成 | ストックしたキーワード/音声から記録フォーマットに整形 | 1 (MVP) |
| 保護者報告の自動生成 | 記録から保護者向けトーンでリライト | 1 (MVP) |
| **セーフティノート(支援者情報共有)** | **LINEで「○○くん」→ アレルギー・苦手な刺激・落ち着く方法・パニック時対応が即返信。臨時対応でも安全に** | **1 (MVP・目玉)** |
| 個別支援計画の下書き | **蓄積された記録を根拠に**、目標・支援内容の草案を生成(児発管が確定) | 2 |
| 活動計画・狙いの下書き | 日々の活動の狙い・流れ・配慮事項・評価の視点を下書き | 2 |
| 加算・書類チェック | 計画未作成減算・モニタリング期限・算定漏れをAIが点検 | 2 |

### 訪問介護向け

| 機能 | 内容 | フェーズ |
|---|---|---|
| **報告の一本化** | 一度話す/送るだけで **①正式報告書 ②記録アプリ入力用 ③サ責向け要約** を同時生成(支援内容・様子・日時・支援者体調) | 2〜3 |
| 移動記録の簡易化 | 開始/終了メーターから走行距離を自動計算。音声入力対応。買い物支援の複数報告も1回に集約 | 2〜3 |
| 買い物支援の効率化 | 過去の依頼履歴をワンタップ候補表示+購入周期からAIが提案(「そろそろ牛乳では?」)。**確定は必ず本人・支援者** | 3 |
| 記録アプリ連携 | ケアピア等との連携はAPI提供があれば直結、なければCSV/コピペ運用から | 3 |

## 4. セーフティノートについて(差別化の核)

「担当者しか知らない」をなくす機能。**時短ではなく安全のための機能**であり、他の記録ツールにない価値。

- 児童ごとの構造化ナレッジ: アレルギー・服薬 / 苦手な刺激 / 落ち着く方法 / パニック時の対応 / 送迎時の注意 / 家庭からの申し送り
- LINEで名前を送る → 臨時対応に必要な要点だけをAIが整理して返信
- 日々の記録から「最近の変化」も反映(例: 「今週は疲れやすい傾向」)
- 効果: 事故予防 / ヘルプ・新人スタッフの心理的安全 / 属人化の解消 / 保護者への説明責任

### この機能の絶対条件(セキュリティ)
最高レベルの要配慮個人情報を扱うため、以下を必須要件とする:

- **アクセス権限管理**: 事業所・役職単位での閲覧範囲制御。LINE連携時は職員個人を認証(なりすまし防止)
- **閲覧ログ**: 誰がいつ誰の情報を見たかを全件記録(監査・抑止)
- **退職者の即時遮断**: アカウント停止で全アクセスを即遮断
- 通信・保存の暗号化 / 国内リージョン / AIへの学習利用なし(オプトアウト)

## 6. 技術構成

```
[入口]
 LINE公式アカウント(Messaging API) ─┐
 Webアプリ(音声入力: Web Speech API)─┤
                                      ▼
[サーバ] 認証・権限 / ストック保存 / 生成API中継 / 閲覧ログ
                                      ▼
[AI] Claude API
  ・記録整形/報告/要約: Haiku 4.5 or Sonnet 5(1件 約0.3〜1円)
  ・計画/活動計画の下書き: Sonnet 5 or Opus 4.8(1件 約2円)
  ・加算チェック: ルール判定+LLMのハイブリッド
  ・プロンプトキャッシュで入力コスト最大約90%削減
                                      ▼
[データ] 児童/利用者マスタ・記録・計画・ナレッジ・加算要件
  ・編集履歴/閲覧ログを保持(監査対応)
```

- AI原価試算: **1事業所あたり月約300〜1,500円**(児童20名規模)。サブスク料金に対し原価はごく小さい
- プロトタイプは引き続きビルド不要の単一HTML。LINE連携は本番フェーズで実装

## 7. 展開戦略

1. **放デイでMVP検証**: 「貯めて→生成」+セーフティノートを協力事業所で実証
2. **放デイで固める**: 計画下書き・加算チェックを追加し、乗り換え困難な存在に
3. **訪問介護へ横展開**: 同じエンジンの上に訪問介護向け書式・機能を展開(姉妹プロダクト or 対応領域拡大は検証後に判断)

### 検証KPI(追加)
- 記録1件あたりの作成時間 / 報告リードタイム(既存)
- **臨時対応時の情報参照率・スタッフ安心度(アンケート)**
- 訪問介護: 報告3形態の作成時間 Before/After、移動記録の入力時間

## 8. リスクと対応

| リスク | 対応 |
|---|---|
| 個人情報漏えい(特にセーフティノート) | 権限管理・閲覧ログ・即時遮断・暗号化・学習オプトアウト |
| LINE経由の情報流出・なりすまし | 職員個人の認証必須。返信内容は要点のみに制限。重要情報はアプリ側で表示 |
| AIの誤生成 | 人のレビュー承認を必須化。計画・報告は下書きと明示 |
| 買い物支援での誤発注 | AIは提案のみ。確定は必ず本人・支援者が承認 |
| 制度改定 | 加算要件をデータ/ルール化し更新可能に |
| 記録アプリ連携ができない | CSV/コピペ運用でも価値が出る設計(3形態同時生成) |
