# 現場視点レビュー — CareOne(訪問介護)検証版

訪問介護員(ヘルパー)とサービス提供責任者(サ責)の立場になりきって、全タブを実際に操作して評価したレビューです。導入判断・今後の開発優先度の材料としてください。

実施日: 2026-08-21 / 対象: CareOne 検証版(全10タブ) / 方法: モバイル幅・PC幅の両方で全画面を操作

---

## 総評

**「記録 → 実績 → 請求」の背骨は実務の流れに合っており、ヘルパーの日々の入力は現行の三重作業(手書き+記録アプリ+口頭申し送り)より明確に軽い。** 一方、事業所として本格導入する判断には「訪問予定の管理」「複数職員での利用」「金銭管理の記録」の3つが本番版で埋まることが条件になる、という感触。

| 立場 | いま使えるか |
|---|---|
| ヘルパー(記録する人) | ◎ 報告・移動・スキャンは今日から時短になる |
| サ責(管理する人) | ○ 請求・要件チェック・申請は強力。ただし予定管理と職員管理がないので既存の手段と併用になる |
| 管理者(導入を決める人) | △ 検証には十分。本番導入は認証・複数端末共有(既知のロードマップ)が前提 |

## 良かった点(現場の言葉で)

1. **📋 報告の「1回話せば3つできる」は本物。** 音声で支援内容を一言入れると、正式報告書・アプリ転記用・サ責向け要約が同時に出る。特に「サ責向け要約」が地味に効く — 電話や事務所での口頭報告が減る
2. **📚 過去の報告の引用が定型訪問に効く。** 週3回同じ生活援助に入る利用者は、前回を引用して差分だけ直せば数十秒で終わる
3. **📷 スキャンの「画像を保存しない」方針が明記されているのが安心。** 利用者宅の紙(バイタル表など)を撮ることに心理的抵抗があるが、「読み取り後に破棄」と画面に書いてあるのは説明しやすい
4. **🧾 請求タブはサ責の実務そのもの。** 加算・減算の内訳、限度額超過の警告、請求前チェック(事業所情報未登録などを指摘)まで一続き。「特定事業所加算の要件チェック」を毎月見るだけで届出の抜けが防げる
5. **📑 申請アシスタントは「一番嫌いな仕事」を代わってくれる。** 加算の届出書類は年に数回しか書かないから毎回調べ直しになる。体制データが自動で入り、参照した文例と根拠が並ぶのは実務的
6. **🏡 利用者一覧の表形式+絞り込み。** 要介護度・負担割合・被保険者番号・今月の報告数が一覧でき、請求前の確認が速い
7. **検証版としての誠実さ。** LIFEが訪問介護では対象外であることを画面に常時明示、AI生成物は必ず人が確認、実名を入れない注意 — 現場に説明できる書き方になっている

## 気になった点(優先度順)

### 高 — 日々の入力のつまずき ✅ 3件とも対応済み(2026-08-21)

1. ✅**対応済み** — 報告タブに「⚡前回の報告をコピー」を追加(1タップで本文・時刻・区分・体調まで復元)。**「前回と同じ」ワンタップがほしい。** 過去報告の引用はあるが、アコーディオンを開いて選んで引用と3タップかかる。定型訪問は「⚡前回コピー」ボタン1つで時刻・区分・本文まで入って良い(ヘルパーは玄関先で立ったまま入力する)
2. ✅**対応済み** — 開始/終了を24時間固定の時・分セレクトに変更(端末ロケール非依存)。**時刻入力が端末依存でAM/PM表示になることがある。** 現場は24時間表記(「17時半」)が常識。iOS/ブラウザの設定次第でAM/PMになると入力ミスの元
3. ✅**対応済み** — 生成失敗時はデモで保存でき「⏳AI再生成待ち」として記録。履歴の「🤖再生成」で後からClaude生成に置換、ダッシュボードに残件数を表示。**電波の悪い環境での生成。** 集合住宅の廊下や山間部では圏外がある。入力・保存は端末内で動くので問題ないが、AI生成は失敗→デモにフォールバックする。**「圏内に戻ったら自動で再生成」の待ち行列**があると現場で迷わない

### 中 — 業務の流れの欠け ✅ 4件とも対応済み(2026-08-22)

4. ✅**対応済み** — 📅予定タブを追加(毎週の曜日指定/日付指定、当日の予定→「▶この予定で報告を作る」で時刻・区分入りの報告へ、報告保存で自動的に報告済み表示)。**訪問予定(スケジュール)がない。** 実務は「予定を組む→訪問する→実績になる」の順で、既存ソフトは予定表が起点。現状は報告=実績のみなので、シフト表・サービス提供票と二重管理になる。**予定登録→当日「開始」タップ→終了時に報告、の流れが本命**
5. ✅**対応済み** — 利用者情報に「🏠訪問時の注意」(鍵・駐車・ペット・禁忌・緊急連絡)を追加。詳細画面の最上部と📋報告画面(利用者選択時のバナー)に表示。**利用者詳細に「その家のルール」欄がない。** 訪問介護は鍵の場所・駐車位置・ペット・禁忌・家族の連絡順など、家ごとの注意事項が命。現在の詳細画面は過去の報告と買い物履歴のみ。**そだちノートのセーフティノートに相当する「訪問時の注意」カード**が欲しい(代替訪問・急な担当変更のときに一番見たい情報)
6. ✅**対応済み** — ホームに⚠️要対応カードを追加(AI再生成待ち/特記事項ありの報告/限度額の超過・接近/特定事業所加算の未整備/今日の未報告予定。タップで該当タブへ)。**ダッシュボードに「要対応」が出ない。** 今日の報告数・移動kmは出るが、サ責が朝一に見たいのは「特記事項ありの報告」「限度額が近い利用者」「要件チェックの警告」。件数だけでも並ぶと巡回が減る
7. ✅**対応済み** — 🛒買い物タブに💰金銭記録(預り金・使用額・おつり自動計算・レシート有無・メモ・履歴)を追加。預り金超過は警告表示。**買い物の金銭管理。** 買い物代行は預り金・レシート・釣り銭の記録が必須(トラブルの最多地帯)。品目の提案だけでなく、金額の記録欄があると監査にも使える

### 低 — あれば嬉しい ✅ 3件とも対応済み(2026-08-22)

8. ✅**対応済み** — 🚗移動に利用者選択を追加。前回の距離・所要時間・目的を「⤵同じ距離・時間で入力」で呼び出せる(開始メーターから終了メーターを自動計算)。**移動の定型ルート。** 事業所⇄利用者宅の距離は毎回ほぼ同じ。利用者を選ぶと前回の距離が入る、で十分
9. ✅**対応済み** — 📑申請アシスタントで「介護職員等処遇改善加算 計画書」を選択可能に(基本情報・職場環境等要件の取組・賃金改善の内容と周知方法の3文書。区分Ⅰ〜Ⅳ選択、職員数を自動反映)。**処遇改善加算の計画書。** 実際は特定事業所加算より処遇改善を出す事業所の方が多いので、次の一手はこれ
10. ✅**対応済み** — 🧾請求タブ→明細書に「サービス提供記録(利用者宅控え)」を追加。対象月の提供実績・担当・確認印欄つきでA4印刷可能。**サービス提供記録の印刷様式。** 完全ペーパーレスまでの移行期は、印刷して置いてくる運用が残る

## タブ別の評点

| タブ | 評点 | 一言 |
|---|---|---|
| 📊 ダッシュボード | ○ | 見た目は良い。「要対応」の集約があれば◎ |
| 📋 報告 | ◎ | 中核機能。前回コピーの1タップ化で完璧 |
| 📷 スキャン | ◎ | 紙が残る現場の現実解。反映先の選択も分かりやすい |
| 🚗 移動 | ◎ | 定型ルートの呼び出しで入力がほぼゼロに |
| 🛒 買い物 | ◎ | 金銭記録の追加で実務に耐える |
| 🧾 実績・請求 | ◎ | サ責の毎月の山場をほぼカバー。単位数の実値検証が次 |
| 🧬 LIFE | ○ | 対象外の明示が誠実。先行実装としては十分 |
| 📑 申請 | ◎ | 特定事業所加算+処遇改善加算の2様式に対応 |
| 🏡 利用者 | ○ | 表形式で管理しやすくなった。「その家のルール」欄が欲しい |
| ⚙️ 設定 | ○ | AI接続・マスタ・バックアップが1か所に整理されている |

## 本番までに必須(再確認)

既知のロードマップと一致: 認証・権限・複数端末共有 / 単位数の実値化 / 国保連伝送。
レビューで挙げた**「高」3件・「中」4件・「低」3件のすべてが対応済み**(2026-08-22)。残るのは本番化項目(認証・権限・複数端末共有 / 単位数の実値化 / 国保連伝送)のみ。
