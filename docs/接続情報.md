## 3. データの保存場所（検証版）

サーバには一切送信されず、**閲覧している端末のブラウザ内だけ**に保存されます。

| アプリ | localStorage キー |
|---|---|
| そだちノート | `sodachi_db_v2` |
| CareOne | `kakehashi_db_v1` |

- 端末・ブラウザを変えるとデータは共有されません
- ブラウザの履歴削除で消えます → ⚙️設定の「バックアップ」（JSON 書き出し）を週1回程度
- 復元は同じ画面の「復元」から

## 4. 本番で接続が必要になるもの

現時点では**すべて未接続**です。契約・申請が必要なものを先に押さえておくと、開発が止まりません。

| 接続先 | 用途 | 必要なもの | 申請の要否・リードタイム |
|---|---|---|---|
| **Claude API**（Anthropic） | 記録・報告・計画の文章生成、**手書き帳票のOCR（vision）**、**申請アシスタントの届出書類下書き（RAG）**。各アプリの `callAI()` をサーバ経由の呼び出しに差し替える | APIキー | 即日。**キーはサーバ側のみに置き、ブラウザには絶対に出さない**。画像もサーバ経由で送る |
| **Firestore(GCP)** | 📑事例ライブラリの**事業所共有**(リレーサーバの `/cases` API)。ConsoleでFirestore作成(ネイティブ・東京)するだけで有効化 | GCPプロジェクト(Cloud Runと同じ) | 任意。未設定でも端末内保存で動作 |
| **埋め込み・ベクトル検索基盤** | 申請アシスタントの事例検索（検証版の文字バイグラム類似を置き換え）。埋め込みAPI＋ベクトルDB（例: pgvector） | 埋め込みAPIキー、DB接続情報 | アプリ用DBと同時に設計。国内リージョン要件は同じ |
| **LINE Messaging API** | そだちノートのキーワード送信・セーフティノート照会 | チャネルアクセストークン、チャネルシークレット、Webhook URL | LINE公式アカウント開設が必要 |
| **電子請求受付システム**（国保連） | 請求データのインターネット伝送・返戻の受取 | **電子証明書**、事業所番号、ユーザID | 証明書の発行申請に日数がかかる。**最優先で着手** |
| **アプリ用データベース** | 記録・実績・請求データの保存（localStorage からの移行先） | 接続文字列、認証情報 | 国内リージョン・保存時暗号化が要件 |
| **職員認証基盤** | ログイン・役職別権限・閲覧ログ | IdP 設定 | 個人情報を扱うため本番では必須 |
| **LIFE**（科学的介護情報システム） | 評価データの提出とフィードバックの取込 | LIFE の**事業所ID・ユーザID**（電子請求受付システムのIDと連動） | 訪問介護は現時点で対象外。通所・施設を併設する場合は取得済みのはず |

### 秘密情報の管理ルール（案）
1. 実際の値は**パスワードマネージャ**（または各クラウドのシークレットストア）に保管し、Notion・リポジトリには置かない
2. リポジトリには `.env.example` のように**キー名だけ**を置く
3. APIキーはサーバ側の環境変数から読む。フロントエンドのコードには絶対に含めない
4. 退職・担当変更時のローテーション手順を決めておく
