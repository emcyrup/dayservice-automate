# 制度改定・法改正への対応方針

「報酬改定に対応してもらえるのか」は、請求機能を持つ以上、導入前に必ず確認される点です。対応できる範囲・対応の仕組み・かかる時間を整理しました。

作成日: 2026-08-15

---

## 1. 何がいつ変わるのか

| 変わるもの | 頻度 | 例 |
|---|---|---|
| **介護報酬改定** | 3年ごと（次は2027年度） | 基本報酬の単位数、加算の新設・廃止・再編 |
| **障害福祉サービス等報酬改定** | 3年ごと（次は2027年度。2024年度は介護と同時改定） | 同上 |
| **加算率の変更** | 随時 | 処遇改善加算の一本化・率改定（2024年6月）など |
| **地域区分・単位単価** | 3年ごと | 級地の見直し |
| **区分支給限度基準額／負担上限月額** | 随時 | |
| **国保連インタフェース仕様書** | ほぼ毎年 | 様式追加、サービスコード追加、項目変更 |
| **運営基準（減算要件）** | 随時 | 虐待防止措置未実施減算・BCP未策定減算の適用開始 |

## 2. 対応の3段階と、かかる手間

| 段階 | 内容 | 対応方法 | 開発 |
|---|---|---|---|
| **① 数値が変わるだけ** | 単位数・加算率・単位単価・限度額 | **マスタの更新のみ**。改定版を作って新しい値を入れる | 不要 |
| **② 加算・減算が増減する** | 新しい加算の新設、廃止 | 単位／回数ベースのものはマスタ追加で概ね吸収。算定条件が複雑なものは判定ロジックの追加 | 小〜中 |
| **③ 算定構造・様式が変わる** | 基本報酬の区分の切り方、請求様式・伝送仕様の変更 | 計算エンジン・帳票の改修 | 中〜大 |

2024年度改定を例にとると、訪問介護の基本報酬引き下げは①、口腔連携強化加算の新設は②、放デイの「専門的支援加算→専門的支援体制加算＋専門的支援実施加算」への再編は③にあたります。**①が大半、③は改定のたびに数項目**というのが実務感覚です。

## 3. 実装済み: 改定版（適用年月）つきマスタ

請求実務で最も事故が起きやすいのが **「4月に行うのは3月分の請求」** という点です。4月1日施行の改定を単純に反映すると、4月に処理する3月分の請求が新しい単位数で計算されてしまいます。

そこで単位数マスタに**適用年月**を持たせ、**請求対象月に応じて自動で版を切り替える**ようにしました。

```
2024-04版 … 2024年4月分 〜 2027年3月分
2027-04版 … 2027年4月分 〜
```

- ⚙️設定の「＋ 新しい改定版」で、現在の版を複製した新しい版を作成（旧版には自動で終了年月が入る）
- 請求画面には「どの版で計算しているか」を常時表示
- 過去月を選べば当時の単位数で再計算されるため、**過月度の再請求・返戻対応にも耐えられる**

両アプリで実装し、改定境界（3月分＝旧単位／4月分＝新単位）をテストで確認済みです。

## 4. 本番でやること

### 4-1. マスタのサーバ配信（SaaSの強み）
検証版は端末内にマスタを持っていますが、本番は**サーバから改定後のマスタを配信**します。事業所側の作業はゼロ。ここが自前のExcel運用や買い切りソフトとの決定的な差になります。

### 4-2. 改定情報の追跡プロセス
1. 告示・通知・Q&A・インタフェース仕様書の更新を監視
2. マスタ更新／必要なら計算ロジックを改修
3. **前年度の実データで新旧を突き合わせ検証**
4. 改定月の前月までに配信、リリースノートで変更点を通知

改定は3年ごとと予測できるため、**施行の半年前（社会保障審議会の答申前後）から準備を始める**のが標準的な進め方です。

### 4-3. 契約での明示
「報酬改定への対応は保守サービスに含む」と明示するのが業界標準です。改定対応を別料金にすると、改定のたびに解約の理由になります。

## 5. 実装済み: 加算定義のデータ化（②の範囲を広げる）

「加算が新設されたらコードを直す」状態を減らすため、**計算ロジックからマスタへ定義を移しました**。加算1つ＝マスタの1行です。

### そだちノート（障害福祉）
| 項目 | 内容 |
|---|---|
| サービスコード | 6桁の体系に変更（`635101` 基本報酬(平日)、`636310` 送迎加算 など）。画面で編集可 |
| 算定単位 | 日ごと／回ごと／月1回／率 |
| 算定のきっかけ | 平日の提供日／休日の提供日／提供日／送迎回数／欠席日／提供があれば1／**手入力** |
| 月上限 | 欠席時対応加算の月4回など、行ごとに設定 |
| 率 | 処遇改善加算などを率で持ち、**適用順**を数値で指定 |
| ON/OFF | 事業所が算定する加算だけチェック |

「きっかけ＝手入力」にした加算は、💴請求タブに**自動で入力欄が現れます**（家庭連携加算のように実施回数で算定するもの）。

### かけはしノート（介護保険）
| 項目 | 内容 |
|---|---|
| 基本報酬 | **時間区分をマスタで持つ**（`mn`分〜`mx`分 → 単位数）。改定で区分の切り方が変わっても行の編集で対応 |
| 以降n分ごと | 開始分数と刻み幅をマスタで指定 |
| 身体＋生活援助 | 20分ごとの単位数と上限回数をマスタで指定 |
| 加算 | 日ごと／回ごと／月1回 × きっかけ（訪問した日／緊急時／初回のある月／訪問があれば1） |
| 率 | 特定事業所・地域加算・虐待防止未実施・BCP未策定・処遇改善を**すべて率の行として管理**（適用順つき） |
| 同一建物減算 | 率の行に「利用者ごとの率を使う」指定。利用者台帳の区分（−10／−15／−12％）を参照 |
| 区分支給限度基準額 | **マスタ化**（要支援1〜要介護5、適用年月つき） |

これにより、**「率の加算・減算が増えた」「限度額が変わった」「時間区分が変わった」はすべてマスタ更新だけ**で対応できます。

## 6. 実装済み: 改定の新旧差分チェック

請求画面に、**同じ実績を2つの版で計算して差額を並べる**画面を用意しました。改定版を作ったら前月の実データで差額を確認してから運用に入る、という手順を機能として組み込んでいます。

## 7. まだコード改修が必要なもの

1. 算定の**条件式**が複雑な加算（例: 特定の資格者が同行した場合のみ、他サービスとの併算定不可など）
2. 請求様式・伝送仕様そのものの変更
3. 新しいサービス種別への対応（児童発達支援、重度訪問介護など）
4. 負担上限月額の区分そのものの変更（現在は児童台帳側で保持）

## 8. まとめ

**随時対応は可能です。** 適用年月つきマスタと加算定義のデータ化により、**数値の変更・加算率の増減・限度額の変更・単位数の変更・多くの加算の新設は開発なしで対応**できます。算定条件が複雑な加算や、様式・伝送仕様の変更は計画的な開発が必要です。

重要なのは、**改定対応を「機能」ではなく「運用プロセス」として設計しておくこと**です。上記4-2のプロセスと保守契約をセットにすることで、事業所側は改定を意識せずに使い続けられます。
