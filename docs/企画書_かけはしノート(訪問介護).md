# かけはしノート ─ 訪問介護の報告AI(企画書 v0.2)

> 訪問介護事業所向けに、**一度の入力から「正式報告書・記録アプリ入力用・サ責向け要約」の3形態を同時生成**し、移動記録・買い物支援の手間も減らすサービス。

作成日: 2026-07-30 / 更新: 2026-08-14(v0.2: **オールインワン方針**に変更 ― 実績・国保連請求・特定事業所加算の要件管理を内蔵) / ステータス: 企画ドラフト
(放課後デイ向け「そだちノート」とは別顧客・別プロダクト。AIエンジン・基盤のみ社内共通)

---

## 1. 背景と課題

| 現場の痛み | 具体的な状況 |
|---|---|
| **報告の三重入力** | ①手書きの報告書 ②記録アプリ(例: ケアピア)への入力 ③サービス提供責任者への口頭/要約報告 ― 同じ内容(支援内容・様子・日時・支援者の体調)を3回作っている |
| 移動記録が手間 | 支援時の移動ごとに走行距離・メーター値・所要時間を報告。買い物支援があると移動・報告回数がさらに増える |
| 買い物支援の非効率 | 利用者が買ってほしい物を選ぶのに時間がかかる |
| 請求業務が別システム | 記録と請求ソフトが分かれ、月末に実績を転記・突合する手間と転記ミス |
| 特定事業所加算の要件管理 | 研修計画・月1会議・事前指示/報告・健診・緊急時対応など、算定要件の記録が分散し、実地指導で指摘されるリスク |

## 2. コンセプト

> **「一度話せば、3つの報告ができている。」**

```
[現場・支援後すぐ]                    [自動生成(3形態同時)]
 音声で話す or ─→ AIが整形 ─┬─→ ① 正式報告書(手書き代替)
 一言メモを送る              ├─→ ② 記録アプリ入力用(ケアピア等)
                             └─→ ③ サ責向け要約
```

## 3. 機能

| 機能 | 内容 | フェーズ |
|---|---|---|
| **報告の一本化** | 一度の入力(音声可)→ 3形態を同時生成。確認してから提出・入力 | 1 (MVP・目玉) |
| 移動記録の簡易化 | 開始/終了メーターから走行距離を自動計算。音声入力対応。履歴一覧 | 1 |
| 買い物支援の効率化 | 過去の依頼履歴をワンタップ候補+購入周期からAIが提案(「そろそろ牛乳では?」)。**確定は必ず本人・支援者** | 2 |
| **請求計算(加算・減算対応)** | **訪問ごとの区分×所要時間から単位数を算定し、2人対応・夜間/深夜・緊急時・初回・特定事業所・地域加算、同一建物/虐待防止未実施/BCP未策定の減算、処遇改善までを反映。区分支給限度基準額の超過も判定** | **2** |
| **実績・国保連請求** | **月次実績から介護給付費明細書・請求書を自動作成し、電子請求受付システムへ伝送。返戻管理まで内蔵** | **2〜3** |
| **特定事業所加算 要件チェック** | **2024年度改定の3要件(体制・人材・重度者等対応)を毎月自動チェック。会議・健診・研修の記録も本アプリに保存し、監査の根拠に** | **2** |
| **帳票スキャン(OCR)** | **手書きの帳票を撮影するだけでAIが読み取り、確認・修正して報告・移動・LIFEへ反映。転記作業と転記ミスをなくす。画像は端末に保存しない** | **2** |
| **LIFE(科学的介護)連携** | **ADL・栄養・口腔・認知症・意欲の評価をLIFE様式で記録し、3か月ごとの提出を管理。日々の報告からAIが評価を下書き。※訪問介護は現時点で対象外のため、2027年度改定と併設法人の法人一括提出を見込んだ先行実装** | **3** |
| サ責ダッシュボード | 要約が自動で集まる一覧。気になる特記事項のアラート | 3 |

### オールインワン方針(v0.2での変更)

**ケアピア等の既存システムとの「併用」を前提にしない。** 記録 → 実績 → 請求 → 伝送までを本アプリ単体で完結させる(移行期のみ3形態出力・CSVで併走可能)。

- 国保連に公開APIはないため、**インターフェース仕様書準拠のCSV + 電子請求受付システムのインターネット伝送**方式(主要請求ソフトと同じ仕組み)
- 検証版は「報告→加算・減算を反映した請求計算→請求サマリー・明細書・請求前チェック→CSV出力」と「特定事業所加算の要件チェック」まで実装済み(加算減算の一覧と適用順は `docs/請求機能_訪問介護.md`)

### 特定事業所加算(2024年度改定)の要件管理

訪問介護の特定事業所加算は**区分Ⅰ(+20%)/Ⅱ(+10%)/Ⅲ(+10%)/Ⅳ(+3%)/Ⅴ(中山間地域)**。売上に直結する一方、要件の記録が揃わず算定を諦める・返還になる事業所が多い。

| 要件群 | 内容(主なもの) | アプリでの扱い |
|---|---|---|
| ① 体制要件(全区分必須) | 訪問介護員ごとの個別研修計画 / おおむね月1回以上の会議+記録 / 文書での事前指示+提供後報告 / 年1回の健康診断(事業主負担) / 緊急時対応方針の明示 | 会議・健診・研修を記録し期限を自動監視。「提供後報告」は日々の報告記録から自動でカウント |
| ② 人材要件(Ⅰ・Ⅱ) | 介護福祉士30%以上 等 | 割合を登録し充足を判定 |
| ③ 重度者等対応要件(Ⅰ・Ⅲ) | 重度要介護者等20%以上 **または** 看取り対応実績(選択式) | 充足状況を登録・判定 |

→ 3要件から**算定可能な区分を毎月自動判定**(最終確認は最新の告示・自治体手引きで)。

## 4. 提供価値

| 価値 | 中身 |
|---|---|
| ⏱ 時短 | 三重入力を1回に。移動報告もその場で数秒 |
| 🧡 質の向上 | 記憶が新しいうちに記録→報告の質が上がる。特記事項の見落とし防止 |
| 🤝 サ責の把握力 | 要約が自動で届き、全利用者の状況把握が容易に |
| ✨ 均質化 | 経験によらず一定水準の報告文 |
| 💰 増収・損失防止 | 特定事業所加算の取りこぼし防止(最大+20%)。要件記録が自動で残り監査にも強い |
| 🗂 一元化 | 記録・実績・請求を1アプリに。月末の転記・突合をゼロに |

## 5. 技術構成

```
[入口] スマホWebアプリ(音声: Web Speech API)/ 将来: LINE入力
[サーバ] 認証 / 保存 / 生成API中継
[AI] Claude API(報告3形態の生成: Haiku/Sonnet ― 1件あたり約0.3〜1円)
[データ] 利用者マスタ・報告・移動記録・買い物履歴(編集履歴保持)
[請求] 実績→給付費明細CSV(国保連インターフェース仕様準拠)→ 電子請求受付システム伝送・返戻取込
[連携] 移行期のみ既存記録アプリ(API or CSV)/ 走行距離は将来 車載・スマホGPS連携も検討
```

- AI原価試算: 1日20件の報告でも**月数百円/事業所**規模
- 利用者の個人情報(要配慮情報)を扱うため、暗号化・アクセス権限・学習オプトアウトは必須

## 6. 検証KPI / リスク

- 報告3形態の作成時間 Before/After / 移動記録の入力時間 / 買い物の品選び時間
- リスク対応: AI誤生成(人の確認後に提出)/ 誤発注(AIは提案のみ・本人確認必須)/ 記録アプリ連携不可(CSV・コピペでも価値が出る3形態同時生成)/ 数字の音声誤認識(メーターは差分自動計算・確認表示)
