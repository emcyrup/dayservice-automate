# LIFE（科学的介護情報システム）連携

かけはしノートに実装したLIFE連携の仕様と、実装にあたっての前提整理です。

作成日: 2026-08-20 / 対象: かけはしノート（訪問介護）

---

## 1. 前提：訪問介護は現時点でLIFEの対象外

**最初に押さえるべき事実です。**

科学的介護推進体制加算をはじめとするLIFE関連加算の対象は、**施設系・通所系・居住系・多機能型**サービスです。訪問介護（ホームヘルプ）は含まれていません。2024年度改定でも訪問系への対象拡大は行われませんでした。

したがって、この機能は**「いま算定に必要だから作る」ものではありません**。それでも実装する理由は3つあります。

| 理由 | 内容 |
|---|---|
| **① 2027年度改定への備え** | 訪問系・居宅介護支援へのLIFE拡大は継続的に議論されています。改定時に慌てずに済む |
| **② 併設法人での法人一括提出** | 通所介護や特定施設を併設する法人では、法人全体でLIFEを運用します。訪問側の記録も同じ様式で持てると、法人単位でのデータ活用ができる（『寿』が「法人全体のデータを統合」を訴求しているのはこの領域） |
| **③ AIによる差別化** | 日々の報告文からLIFE評価の下書きを作れるのは、既存の介護ソフトにはない価値。ここは訪問介護でも今すぐ効く |

画面上部にも「訪問介護は対象外・先行実装である」旨を常時表示しています。**顧客に誤解を与えないことを優先**しました。

## 2. 参考にした製品

**介護トータルシステム『寿』**（株式会社南日本情報処理センター）。全介護サービス対応で、LIFE・タブレット・介護ロボット連携を備え、法人全体のデータを1つに統合できる点を訴求しています。買い切り型で、報酬改定にはバージョンアップで無償対応。

ここから読み取った要件は次の2つです。

1. **サービス種別をまたいで同じ利用者情報を持つ**こと（法人統合）
2. **報酬改定・LIFE様式変更への追随を売り物にする**こと（本アプリでは適用年月つきマスタで対応済み）

## 3. 実装した機能

### 3-1. 評価入力（LIFE様式に沿った項目）

| 区分 | 内容 |
|---|---|
| **① ADL** | Barthel Index 10項目（食事・移乗・整容・トイレ動作・入浴・歩行・階段昇降・更衣・排便・排尿）＝100点満点。合計を自動計算し、85点以上/60点以上/それ未満で色分け |
| **② 栄養** | 身長・体重から**BMIを自動計算**。18.5未満は「低体重（低栄養リスク）」を警告 |
| **③ 口腔** | 食べこぼし・むせ・歯や義歯の汚れ・義歯不適合・口腔乾燥 |
| **④ 認知症の行動・心理症状** | **DBD13**（13項目 × 0〜4点＝52点満点）。過去1週間の状況 |
| **⑤ 意欲** | **Vitality Index**（起床・意思疎通・食事・排泄・活動 × 0〜2点＝10点満点） |
| **⑥ その他** | 服薬中の薬剤数、特記事項 |

前回の評価が初期値として復元されるため、3か月ごとの再評価は**変わったところだけ直せば済みます**。

### 3-2. 🤖 報告からのAI下書き（差別化ポイント）

日々の報告文をAIが読み、評価に関係しそうな記述を拾って提示します。

| 報告文中の記述 | AIが示す評価の当たり |
|---|---|
| むせ・咳き込み | ③口腔「むせ」→ **自動でチェック** |
| こぼす・食べこぼし | ③口腔「食べこぼし」→ 自動でチェック |
| 義歯・入れ歯 | ③口腔「義歯が合わない」の確認 |
| 転倒・ふらつき・つまずき | ①ADL「歩行」「移乗」の見直し |
| 食欲がない・体重が減った | ②栄養のBMI確認、低栄養リスクの検討 |
| 眠れない・夜中 | ④DBD13「夜中に起き出す」の確認 |
| 意欲・閉じこもり | ⑤意欲の見直し |

**判断は必ず担当者が行う**前提で、あくまで見落とし防止の下書きです。3か月に1度の評価では記憶に頼りがちな部分を、日々の記録で裏付けられます。

### 3-3. 📅 提出管理

LIFEへの提出は原則**3か月に1回**。利用者ごとに最終評価日・最終提出日・次回期限・状態（期限内／まもなく期限／期限超過／未提出／未評価）を一覧で表示します。「提出済にする」で提出日を記録すると、次回期限が3か月後に更新されます。

### 3-4. 📈 経過

過去8回の評価を並べ、前回との差を矢印で表示します。ADL・意欲は上がるほど良いので上昇を緑、DBD13は下がるほど良いので低下を緑にしています。LIFEのフィードバックと突き合わせて支援の見直しに使う想定です。

### 3-5. 📤 提出データ

LIFEのCSV連携仕様に沿った形でCSVを出力します。事業所番号・被保険者番号・氏名・評価日に、ADL各項目・BMI・口腔・DBD13・意欲・薬剤数を並べます。

## 4. 未実装（本番開発項目）

1. **正式な様式・項目定義への突合** — 現在は項目構成の試作。厚生労働省の[LIFE CSV連携仕様書](https://www.mhlw.go.jp/content/12301000/001242214.pdf)（令和6年4月・3.00版）に合わせて確定する
2. **LIFEへの直接アップロード** — 現在はCSV出力まで
3. **フィードバック票の取り込み** — 加算要件は「提出」だけでなく「**フィードバックの活用**」まで含むため、本番では必須。事業所平均との比較・経時変化を取り込み、ケアの見直し画面につなげる
4. 興味・関心チェックシート、口腔・栄養スクリーニング、排せつ支援など**他様式への対応**
5. 通所介護・特定施設など**他サービス種別への展開**（法人一括提出の本命）
