# 国保連請求のオールインワン実装メモ

そだちノート / かけはしノート を「記録から請求まで1つのアプリで完結」させるための、請求まわりの調査結果と実装状況をまとめたものです。

作成日: 2026-08-15 / ステータス: 調査中（正式仕様書の突合が未完了）

---

## 1. 結論：APIはなく「仕様準拠CSV＋伝送」で実装する

国保連合会に、事業所システムから直接請求を投げる公開APIは**ありません**。市販の請求ソフトも例外なく、次の2段構えです。

1. 厚生労働省が公開する**インタフェース仕様書**に準拠した請求データ（CSV／固定長）を作成する
2. **電子請求受付システム**にインターネット経由で伝送する（電子証明書が必要）

したがって本アプリも同じ方式を取ります。「APIがないから連携できない」のではなく、**仕様書どおりのファイルを作れれば市販ソフトと同等**です。

## 2. ファイル構造（仕様書で確認できた共通ルール）

| 項目 | 内容 |
|---|---|
| レコード形式 | 可変長レコード |
| 区切り文字 | カンマ `,`（16進 0x2C） |
| 改行コード | CRLF（16進 0x0D0A） |
| 構成 | **コントロールレコード / データレコード / エンドレコード** の3種類で1つの論理ファイル |
| コントロールレコード | 先頭。レコード種別＝`1`、データ種別（後続データレコードの交換情報識別番号の上位3桁）、レコード件数、送付元情報など |
| データレコード | レコード種別＝`2` ＋ レコード番号（連番）を先頭に付け、以降に各様式の項目を並べる |
| エンドレコード | 末尾。レコード種別＝`3` |
| レコード件数 | 総レコード数からコントロール・エンドを除いた件数 |

明細書情報は複数レコードの組み合わせで構成され、**基本情報レコード**（市町村・受給者・請求事業所などの基本情報）と**明細情報レコード**（サービスコード・請求単位数など）に分かれます。

### 未確定事項（正式仕様書での突合が必要）

- **交換情報識別番号**の正確な値（サービス種別・様式ごとに異なる）
- 各レコードの**項目順・桁数・必須/任意**の確定
- **文字コード**：仕様は Shift_JIS 系。ブラウザの `TextEncoder` は UTF-8 のみのため、本番はサーバ側または変換テーブルで対応する
- ファイル名の命名規則

> 参照すべき一次資料は厚生労働省の「インタフェース仕様書（共通編／事業所編）」最新版（令和7年4月版など）。本調査時点では環境のネットワーク制限により当該PDFを直接取得できておらず、検索結果から確認できた共通ルールのみを反映しています。**実装前に必ず最新版PDFで項目定義を突合してください。**

## 3. 現在の実装状況（検証版）

| 機能 | そだちノート | かけはしノート |
|---|---|---|
| 事業所情報（事業所番号・名称・市町村/保険者番号） | ✅ ⚙️設定 | ✅ ⚙️設定 |
| 日々の実績入力 | ✅ 出欠・開始/終了・送迎(往復) | ✅ 報告から開始/終了/提供分数を自動取得 |
| 月次集計 | ✅ 利用日数・欠席・送迎回数・支給量比較 | ✅ 提供回数・提供時間 |
| **提供実績記録票の様式プレビュー** | ✅ 月間グリッド＋印刷（A4縦） | ― |
| **金額計算**（単位数→総費用額→給付費／利用者負担） | ✅ 単位数マスタ・地域区分単価・体制加算・処遇改善率に対応 | ⛔ 本番（介護保険は別体系） |
| **給付費明細書** | ✅ 画面プレビュー | ⛔ 本番 |
| **利用者負担上限額管理結果票** | ✅ 管理結果1〜3の自動判定・順次充当 | ― （介護保険は高額介護サービス費で別扱い） |
| **請求前チェック** | ✅ 期限・支給量・上限管理・計画未作成 | ⛔ 本番 |
| 請求データ（3レコード構成） | ✅ 試作・プレビュー＋CSV出力 | ✅ 試作・プレビュー＋CSV出力 |
| 電子請求受付システムへの伝送 | ⛔ 本番実装 | ⛔ 本番実装 |
| 返戻・過誤の取込／管理 | ⛔ 本番実装 | ⛔ 本番実装 |

**請求データ（試作）の現在の並び**

```
1,<データ種別>,<レコード件数>,<送付元事業所番号>,<作成年月日>      ← コントロール
2,<連番>,<交換情報識別番号>,<市町村番号>,<事業所番号>,<サービス提供年月>,...  ← データ
3                                                                  ← エンド
```

構造は仕様どおり、**中身の項目定義は暫定**です。仕様書突合後は、この並びを定義テーブルとして外出しし、様式追加に耐えられる形にします。

## 4. 本番までのロードマップ

1. **仕様突合**：最新インタフェース仕様書で交換情報識別番号・項目定義を確定 → 定義テーブル化
2. **文字コード対応**：Shift_JIS 出力（サーバ側変換）
3. **伝送**：電子請求受付システム連携。電子証明書の取得・管理フロー設計
4. **返戻対応**：返戻データの取込と、原因（受給者証期限切れ・支給量超過など）の自動特定 → 該当児童/利用者へのリンク
5. **上限管理**（そだちノート）：利用者負担上限額管理結果票の作成

なお、返戻の主要因である「受給者証の期限切れ」「契約支給量の超過」は、**請求前チェックとして既に✅加算タブに実装済み**です。オールインワン化の価値は、この「請求してから返戻で気づく」を「入力時点で防ぐ」に変える点にあります。
