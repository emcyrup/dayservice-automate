# 現場検証ガイド(そだちノート / CareOne 検証版)

協力事業所のみなさまに、検証版アプリを1〜2週間お試しいただくためのガイドです。

## アクセス方法

| アプリ | 対象 | URL |
|---|---|---|
| 🌱 そだちノート | 放課後等デイサービス | https://emcyrup.github.io/dayservice-automate/ |
| 💙 CareOne(旧かけはしノート) | 訪問介護 | https://emcyrup.github.io/dayservice-automate/houmon/ |

- スマホの **Chrome / Safari / Edge** で開いてください(音声入力対応)
- ホーム画面に追加(ブックマーク)しておくとアプリのように使えます

## ⚠️ 検証時のお願い(重要)

1. **実名は入力しないでください。** 児童・利用者は必ずイニシャルや仮名(例: Aくん、Bさん)で登録してください。検証版は認証・暗号化のない試用環境です。
2. データは**お使いの端末のブラウザ内にのみ**保存されます(サーバには送信されません)。
   - 端末やブラウザを変えるとデータは共有されません
   - ブラウザの履歴削除でデータが消えることがあります → **⚙️設定→バックアップ** を週1回程度お願いします
3. **AIの生成文はデモ用の簡易版**です。本番はClaude(生成AI)による自然な文章になります。今回の検証では「この流れ・操作感が業務に合うか」を見てください。

## はじめに(初期設定・5分)

1. 右上の **⚙️(設定)** を開く
2. 「🧹 サンプルを削除」でデモデータを消す(CareOneは初回起動時に、報告・移動・予定・金銭・メモ・LIFEのデモデータが入っています。まず一通り触ってみてから削除するのがおすすめです)
3. **事業所情報**(事業所番号・事業所名・市町村/保険者番号)を登録 ― 実績記録票・請求データの検証に使います(仮の番号で構いません)
4. **👦児童タブ(CareOneは🏡利用者タブ)** の「＋ 追加」から、実際の児童/利用者を**仮名で**数名登録
   - 一覧の各行にある「編集」からいつでも修正できます
   - そだちノートは**セーフティノート情報**(アレルギー・苦手・落ち着く方法・パニック時対応・送迎注意)もぜひ入力してください ― 👥共有タブの検証に必要です

## 試していただきたいこと

### 🌱 そだちノート(放デイ)

| # | シナリオ | 見ていただきたい点 |
|---|---|---|
| 1 | 活動中、💬記録タブでキーワードを2〜3個送る(1日数回) | その場の数秒メモが負担にならないか |
| 2 | 閉所後「貯めたメモから記録を生成」→ 保存 | 記録作成が何分短くなるか |
| 3 | ✉️報告タブで保護者向け文章を生成 | トーン・内容は使えそうか |
| 4 | 👥共有タブで児童名を送る(特にヘルプ・臨時の場面を想定) | 臨時対応に必要な情報が揃っているか。項目の過不足 |
| 5 | 📝計画タブで支援計画・活動計画の下書き | たたき台として時短になるか |
| 6 | 🗓実績タブで毎日の出欠・送迎を記録 → 月末に「実績記録票を表示」→ 印刷 | **今お使いの実績記録票と項目が合っているか**。この入力なら毎日続けられるか |
| 7 | ✅加算タブで受給者証の期限・支給量超過の警告を確認 | 返戻の予防として役に立つか |
| 8 | ⚙️設定で単位単価・体制加算・単位数マスタを実際の値に更新 → 💴請求タブで「集計する」 | **金額が実際の請求額と一致するか**(ここが最重要) |
| 9 | 💴請求タブの請求前チェック・給付費明細書・上限額管理結果票を確認 | いま使っている請求ソフトの代わりになりそうか。足りない項目は何か |

| 1d | 保存した報告を履歴から**✏️編集**・**🖨印刷**・**🗑削除**してみる。履歴を利用者や対象月で絞り込む | 書き間違いを直せるか。**実地指導で「◯月◯日の記録を」と言われて出せるか** |
| 1b | 移動中や訪問直後に📊ダッシュボードの**✍️その場でメモ・録音**で一言残す → あとから「📋報告へ送る」 | 思い出したことをその場で残せるか。報告作成時に拾えて楽になるか |
| 1c | 💬AI相談タブで、いま困っていること(加算の要件・届出の手順・記録の書き方・アプリの操作)を聞いてみる | 聞きたいことに答えが返るか。**「誰に聞けばいいか分からない」場面の代わりになるか**。参照された事例は妥当か |
| 2 | 移動のたびに🚗移動タブでメーター入力 | 従来の距離報告より楽か |
| 3 | 🛒買い物タブで「いつもの品」から選ぶ | 品選びの時間が短くなるか。「AIの提案」は役に立ちそうか |
| 4 | 🧾実績・請求タブで月次実績を確認 | 報告からの自動集計が実際の提供実績と合っているか |
| 5 | 🧾実績・請求タブの**特定事業所加算 要件チェック**に体制情報を入力 | 要件の項目・判定が実態と合っているか。要件管理の手間が減りそうか |
| 6 | ⚙️設定で単位単価・特定事業所加算区分・処遇改善率・単位数マスタを実際の値に更新 → 🧾実績・請求で「集計する」 | **単位数・金額が実際の請求額と一致するか**(ここが最重要) |
| 7 | 利用者情報に要介護度・負担割合・同一建物区分を登録し、明細書を確認 | 加算・減算の内訳が実際の算定と合っているか。限度額超過の警告は役に立つか |
| 7b | 🏡利用者に氏名カナ・生年月日・性別・認定有効期間・居宅介護支援事業所番号を登録 → 🧾請求→📤請求データの**「国保連へ伝送するために必要なもの」**、🧬LIFE→📤提出データの**「LIFEへ提出するために必要なもの」**を確認 | 実際の請求・提出に必要な項目が揃っているか。**足りないものの示し方**は分かりやすいか(必要な情報の一覧は[提出に必要な情報.md](提出に必要な情報.md)) |
| 8 | 📷スキャンタブで**実際にお使いの手書き帳票を撮影** → 読み取り結果を確認 → 報告に反映 | **読み取り項目が実際の様式と合っているか**。転記がどれだけ楽になるか(※検証版は実際の読み取りは行いません) |
| 9 | 🧬LIFEタブで「報告から下書きを作る」→ 評価を入力・保存 | AIが拾った内容は実態と合っているか。3か月ごとの評価がこの入力なら続けられるか(※訪問介護は現在LIFE対象外の先行機能) |
| 10 | 2回目以降の評価で「📚過去の評価を参照」→ 引用 → 差分だけ修正して保存 | **前回を土台にする流れで再評価が楽になるか**。参照画面の項目は足りているか |
| 11 | 📑申請タブで「事例を参照して下書きを作る」→ 特定事業所加算の届出一式を確認。📚事例ライブラリに自事業所の文例を1件追加して再生成 | 実際の届出書類と項目が合っているか。**事例を貯めるほど下書きが良くなる仕組み**は運用できそうか |
| 11b | 下書きを「④ 採用して次回に活かす」で**提出できる形に直してから「👍採用」** → もう一度生成して、前回の書き方が反映されるか確認 | **直した文章が次回の土台になる**流れが実務に合うか。何回か回すと「自事業所の型」になっていくか |
| 12 | 📑申請タブで様式を「介護職員等処遇改善加算 計画書」に切り替えて生成 | 3文書(基本情報・職場環境等要件・賃金改善)の構成が実際の様式と合っているか |
| 13 | 🧾実績・請求→📄明細書の「サービス提供記録(利用者宅控え)」を表示→印刷 | **今お使いの複写式の紙と項目が合っているか**。利用者宅に置く控えとして使えるか |
| 14 | 🚗移動で利用者を選び、2回目以降に「⤵同じ距離・時間で入力」 | 毎回の距離入力が省けるか |

- **Before**: 現在の記録/報告にかかっている時間(1件あたり・1日あたり)
- **After**: アプリ使用時の時間
- 「使わなくなった機能」とその理由(最重要のフィードバックです)

## 検証版の制限事項(本番との違い)

| 項目 | 検証版 | 本番(予定) |
|---|---|---|
| AI生成 | デモ用の簡易生成（CareOneは⚙️設定でAIサーバを設定するとClaude生成に切替可能。💬AI相談もデモ回答→Claude回答に切り替わります） | Claude APIによる自然な文章生成 |
| データ保存 | 端末内のみ | 暗号化クラウドDB・事業所内で共有 |
| ログイン・権限 | なし(→実名禁止) | 職員認証・役職別の権限・閲覧ログ |
| LINE連携 | なし(アプリ内で体験) | LINE公式アカウントから送信・照会 |
| 記録アプリ連携 | コピー機能まで | 移行期のみAPI/CSV連携(以後はアプリ内で完結) |
| 国保連請求 | 金額計算・明細書・上限額管理・請求前チェック・試作CSVまで | 様式準拠の請求データ作成→電子請求受付システムへ伝送→返戻管理 |
| 単位数 | **暫定値**(⚙️設定で編集可能) | 報酬改定に合わせたマスタ配信 |
