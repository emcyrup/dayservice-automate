# 福祉現場の記録・共有AI（2プロダクト）

別々のお客様向けの、独立した2つのアプリの企画＆プロトタイプです。AIエンジン（「貯めて→生成」）と技術基盤は社内で共通化しつつ、プロダクト・データ・契約は完全に分離しています。

**方針: オールインワン。** 既存の記録・請求システムとの併用を前提とせず、記録 → 実績 → 国保連請求（給付費明細CSV → 電子請求受付システム伝送）→ 返戻管理までを各アプリ単体で完結させます（検証版は実績記録票の様式表示・請求データ試作・CSV出力まで実装）。請求まわりの調査結果と実装状況は **[`docs/国保連請求_仕様メモ.md`](docs/国保連請求_仕様メモ.md)**、請求機能の要件・計算仕様は **[`docs/請求機能_要件一覧.md`](docs/請求機能_要件一覧.md)**（障害福祉／放デイ）と **[`docs/請求機能_訪問介護.md`](docs/請求機能_訪問介護.md)**（介護保険／訪問介護・加算減算の一覧と適用順）を参照。
報酬改定への対応方針（適用年月つきマスタ・改定時の運用プロセス）は **[`docs/制度改定への対応方針.md`](docs/制度改定への対応方針.md)** を参照。
LIFE（科学的介護情報システム）連携の仕様と前提は **[`docs/LIFE連携.md`](docs/LIFE連携.md)** を参照。
手書き帳票のOCR連携は **[`docs/帳票スキャン(OCR).md`](docs/帳票スキャン(OCR).md)** を参照。
過去事例をもとに帳票・申請書類を作るAI基盤(Claude + RAG構成。専用LMを学習しない理由を含む)は **[`docs/AI基盤_構成方針.md`](docs/AI基盤_構成方針.md)** を参照。
国保連への伝送・LIFEへの提出に必要な情報(事業所側・利用者側・様式側の項目と、いま足りないもの)は **[`docs/提出に必要な情報.md`](docs/提出に必要な情報.md)** を参照。

## 🌱 そだちノート（放課後デイサービス）

「その場では、送るだけ。書類は、ボタン一発。」＋「名前を入れれば、配慮点がわかる。」

| タブ | 内容 |
|---|---|
| 🏠 ホーム | 児童一覧・当日の記録数・未生成メモ |
| 💬 記録 | キーワードを送って貯める（LINE風）or 音声 → AIが活動記録に整形 |
| ✉️ 報告 | 記録から保護者向け報告文を自動生成（送信前レビュー前提） |
| 📝 計画 | 蓄積記録＋アセスメントから個別支援計画／活動計画・狙いの下書き |
| 🗓 実績 | 出欠・提供時間・送迎を記録 → 月次実績を自動集計＋**サービス提供実績記録票**の様式表示・A4印刷 |
| 💴 請求 | 実績から**総費用額・給付費・利用者負担額を自動計算**。請求サマリー／給付費明細書／**利用者負担上限額管理結果票**／請求前チェック／請求データCSV |
| ✅ 加算 | 計画未作成・モニタリング期限・受給者証期限・支給量超過・加算の取りこぼしを点検 |
| 👥 共有 | セーフティノート：名前を送ると配慮点（アレルギー・パニック時対応等）が返る |

## PWA(ホーム画面に追加・オフライン起動)

両アプリとも **PWA** です。スマホのブラウザで開いて「ホーム画面に追加」すると、アドレスバーのないアプリとして起動します。

- **圏外でもアプリが開きます** — マンションの廊下・地下・山間部でも記録の入力・閲覧・印刷ができます(AI生成だけはオンラインが必要)
- オフラインになると画面下に案内が出ます。新しいバージョンが配信されると「更新」の案内が出ます
- ⚙️設定 →「📱 アプリとして使う」で、インストール状況・オフライン起動の可否・配信バージョンを確認できます
- 配信物を更新したら [`sw.js`](sw.js) の `CACHE_VERSION` を上げてください

構成: [`sw.js`](sw.js)(両アプリ共通のService Worker)/ [`manifest.webmanifest`](manifest.webmanifest)・[`houmon/manifest.webmanifest`](houmon/manifest.webmanifest) / `icons/`・`houmon/icons/`。
Service Workerが扱うのは**同一オリジンのGETだけ**で、AIリレーサーバへの通信には一切触れません。

## 動かし方

各 `index.html` をブラウザで開くだけです。ビルドもインストールも不要。

```bash
python3 -m http.server 8000
# → http://localhost:8000/         （そだちノート）
# → http://localhost:8000/houmon/  （CareOne）
```

> 🎤 音声入力はブラウザ標準の Web Speech API を使用。**Chrome / Edge / Safari** 推奨。スマホで開くと現場での使用感を確認できます。
> 📱 Service Worker は `https://` または `http://localhost` でのみ動きます(`file://` で直接開いた場合はオフライン起動が無効になります)。

## 技術メモ

- フレームワークなしの静的Webアプリ（HTML/CSS/JS）。スマホファースト。ライト／ダークテーマ対応。
- データは `localStorage`（プロト用。本番はDB＋権限管理＋閲覧ログへ）。CareOneは**初回起動時にデモデータ**（報告12件・バイタル7件・移動8件・予定3件・金銭3件・メモ3件・事前指示3件・ヒヤリハット2件・苦情/相談2件・会議/研修4件・個別研修計画・LIFE2件）が入り、⚙️設定の「🧹 サンプルを削除」で利用者ごと消えます。
- 利用者情報は請求・LIFEに必要な項目（氏名カナ・生年月日・性別・認定有効期間・居宅介護支援事業所番号・保険者番号）まで登録でき、未登録は🧾請求／🧬LIFEの「必要なものチェック」に一覧表示されます。
- **AI生成はデモ用の内蔵ジェネレータ**。CareOneは **[`server/`](server/) のAIリレーサーバ**を立てて⚙️設定にURLを入力すると、報告・LIFE下書き・帳票OCR・申請下書きが **Claude API による本物の生成**に切り替わる（APIキーはサーバ側のみ・ブラウザに出さない）。
- そだちノートの本番LINE連携は LINE Messaging API を想定。

## 注意

AIの生成物（記録・報告・計画）は**必ず人が確認・承認してから確定/送信**する運用を前提としています。
児童・利用者の個人情報を扱うため、本番化には暗号化・アクセス権限・閲覧ログ・学習オプトアウト等のセキュリティ対応が必須です。詳細は各企画書を参照してください。
