# 福祉現場の記録・共有AI（2プロダクト）

別々のお客様向けの、独立した2つのアプリの企画＆プロトタイプです。AIエンジン（「貯めて→生成」）と技術基盤は社内で共通化しつつ、プロダクト・データ・契約は完全に分離しています。

**方針: オールインワン。** 既存の記録・請求システムとの併用を前提とせず、記録 → 実績 → 国保連請求（給付費明細CSV → 電子請求受付システム伝送）→ 返戻管理までを各アプリ単体で完結させます（検証版は実績集計・CSV出力まで実装）。

| プロダクト | 対象 | プロトタイプ | 企画書 |
|---|---|---|---|
| 🌱 **そだちノート** | 放課後等デイサービス | [`index.html`](index.html) ／ [公開デモ](https://emcyrup.github.io/dayservice-automate/) | [`docs/企画書_そだちノート(放デイ).md`](docs/企画書_そだちノート(放デイ).md) |
| 🧡 **かけはしノート** | 訪問介護 | [`houmon/index.html`](houmon/index.html) ／ [公開デモ](https://emcyrup.github.io/dayservice-automate/houmon/) | [`docs/企画書_かけはしノート(訪問介護).md`](docs/企画書_かけはしノート(訪問介護).md) |

## 🌱 そだちノート（放課後デイサービス）

「その場では、送るだけ。書類は、ボタン一発。」＋「名前を入れれば、配慮点がわかる。」

| タブ | 内容 |
|---|---|
| 🏠 ホーム | 児童一覧・当日の記録数・未生成メモ |
| 💬 記録 | キーワードを送って貯める（LINE風）or 音声 → AIが活動記録に整形 |
| ✉️ 報告 | 記録から保護者向け報告文を自動生成（送信前レビュー前提） |
| 📝 計画 | 蓄積記録＋アセスメントから個別支援計画／活動計画・狙いの下書き |
| 🗓 実績 | 出欠・提供時間・送迎を記録 → 月次実績を自動集計・CSV出力(国保連請求へ) |
| ✅ 加算 | 計画未作成・モニタリング期限・受給者証期限・支給量超過・加算の取りこぼしを点検 |
| 👥 共有 | セーフティノート：名前を送ると配慮点（アレルギー・パニック時対応等）が返る |

## 🧡 かけはしノート（訪問介護）

「一度話せば、3つの報告ができている。」

| タブ | 内容 |
|---|---|
| 🏠 ホーム | 利用者一覧・今日の報告数・走行km |
| 📋 報告 | 一度の入力（音声可）→ 正式報告書／記録アプリ用（ケアピア等）／サ責向け要約を同時生成 |
| 🚗 移動 | 開始・終了メーターから走行距離を自動計算 |
| 🛒 買い物 | 過去依頼のワンタップ候補＋購入周期からのAI提案（確定は必ず本人・支援者） |
| 🧾 実績・請求 | 報告から月次実績を自動集計・CSV出力＋特定事業所加算(2024改定)の要件チェック |

## 現場検証について

検証版として、⚙️設定画面(児童/利用者の追加・編集、バックアップ/復元、サンプルデータ削除)を備えています。
協力事業所での試用手順・お願い・フィードバック観点は **[docs/検証ガイド.md](docs/検証ガイド.md)** を参照してください。
**検証時は実名を入力せず、仮名でお試しください**(検証版は認証・暗号化のない試用環境です)。

## 動かし方

各 `index.html` をブラウザで開くだけです。ビルドもインストールも不要。

```bash
python3 -m http.server 8000
# → http://localhost:8000/         （そだちノート）
# → http://localhost:8000/houmon/  （かけはしノート）
```

> 🎤 音声入力はブラウザ標準の Web Speech API を使用。**Chrome / Edge / Safari** 推奨。スマホで開くと現場での使用感を確認できます。

## 技術メモ

- フレームワークなしの静的Webアプリ（HTML/CSS/JS）。スマホファースト。ライト／ダークテーマ対応。
- データは `localStorage`（プロト用。本番はDB＋権限管理＋閲覧ログへ）。
- **AI生成はデモ用の内蔵ジェネレータ**。本番は各アプリの `callAI()` を Claude API 呼び出し（サーバ経由）に差し替えるだけで動くよう分離。
- そだちノートの本番LINE連携は LINE Messaging API を想定。

## 注意

AIの生成物（記録・報告・計画）は**必ず人が確認・承認してから確定/送信**する運用を前提としています。
児童・利用者の個人情報を扱うため、本番化には暗号化・アクセス権限・閲覧ログ・学習オプトアウト等のセキュリティ対応が必須です。詳細は各企画書を参照してください。
